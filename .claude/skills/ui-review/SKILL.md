# 前端展示前檢查

目標是在面試前找出會被挑出的問題，不是給稱讚。只回報，確認後才改。

## 步驟

1. 範圍：使用者指定檔案時只看那些；否則檢查 `web/src` 全部與 `api/types/clinic-api.ts`。
2. 執行 `cd web; npm run build`，記錄型別錯誤。
3. 依下方清單閱讀程式碼，每個問題附 `檔案:行號`，並寫出面試官可能怎麼問。
4. 需要實際互動驗證時，啟動 API 與 `npm run dev`，在瀏覽器確認：鍵盤操作、手機寬度（400px）不破版、停掉 API 時的錯誤訊息。
5. 輸出報告，依嚴重度排序：
   - **必修**：bug、型別錯誤、競態、錯誤沒有顯示、個資外洩、前後端型別不一致。
   - **建議**：可讀性、命名、缺少的邊界狀態、可抽出的元件。
   - **加分**：讓 demo 更清楚的小改動。
6. 詢問使用者要修哪些項目，確認後再改。

## 檢查清單

**TypeScript 與型別一致**
- 沒有 `any`、不必要的 `as`、`!`。
- API 型別只來自 `api/types/clinic-api.ts`；對照 `api/Dtos/*.cs`，欄位名稱（camelCase）與可為 null 的欄位一致。

**正確性**
- 每個查詢區塊有載入中、空資料、錯誤、正常四種畫面。
- 連續觸發的查詢（切換病人、切換天數、換日期）有處理競態，過期回應不會覆蓋新資料。
- 寫入操作（報到）執行中 disabled；409 時顯示後端訊息，畫面狀態不會被錯誤改掉。
- 日期用本地 `yyyy-MM-dd`，沒有 `toISOString()` 造成跨日錯誤；量測時間沒有被當成 UTC 轉換。
- `null` 數值顯示「—」，不是 `null` 或空白造成誤判。

**API 使用**
- 只透過 `api/client.ts`；沒有散落的 `fetch`。
- 非 2xx 與 body 不是 JSON（API 停掉、proxy 502）都有可讀的錯誤訊息。

**個資（醫療資料）**
- 病人姓名、病歷號沒有寫進 `localStorage` / `sessionStorage`、URL、`console.log`。
- 畫面只顯示需要的欄位。

**無障礙與互動**
- 可點擊元素是 `<button>`；鍵盤可操作，focus 看得到。
- 表單欄位有 `<label>`。
- 狀態不只靠顏色（徽章有文字）。

**RWD 與展示**
- 400px 寬不破版，寬表格可水平捲動。
- 頁面看得出在展示什麼（標題、空狀態提示文字）。
